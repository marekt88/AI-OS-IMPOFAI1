# Integracie: strojove napojenie na systemy VO (SR + EU)

Agent: INTEGRACIE | Round 1 | Datum overovania: 25. 9. 2026
Pohlad: prisny overovatel. Za **OVERENE** povazujem len to, kde som nacital dokumentacnu stranku a uvadzam URL. Zmienka v tlacovej sprave, na blogu alebo vo forovom prispevku nie je API.

## Zistenia

### Hlavny vysledok v jednej vete

Strojovo dobre pokryte je **EU jadro (TED) a slovenske registre na overovanie uchadzacov**. Strojovo NEpokryty je **samotny priebeh slovenskeho VO** - IS EPVO (byvale IS EVO), IS eForms UVO a registre UVO nemaju verejnu API dokumentaciu. To je najvacsie integracne riziko platformy.

## Dôkazy

Vsetky URL nizsie som nacital 25. 9. 2026.

**EU / TED**
- `https://docs.ted.europa.eu/api/latest/index.html` - TED API v3.0, vsetky endpointy na `https://api.ted.europa.eu/v3/{resource}/{action}`, Swagger na `https://api.ted.europa.eu/swagger`. Doslovne: vsetky endpointy pracujuce s nezverejnenymi oznameniami vyzaduju API kluc; Search API ho nevyzaduje. TED API 2.0 je podporovane pocas prechodu.
- `https://docs.ted.europa.eu/api/latest/search.html` - `POST /v3/notices/search`, bez autentifikacie, XML pre hromadne stahovanie, hierarchie CPV a NUTS. Preview prostredie Search API nepodporuje, len produkcia.
- `https://docs.ted.europa.eu/home/index.html` - prehlad sad dokumentacie a verzii: eForms SDK **1.15**, TED API **3.0**, eProcurement Ontology **5.2.0**, TED Open Data **1.0**, ESPD-EDM **4.1.0**, Model2Owl 3.1.0.
- `https://docs.ted.europa.eu/ODS/latest/index.html` - Linked Open Data + SPARQL, bulk XML, CSV podmnoziny cez data.europa.eu, FTP archiv schem.
- `https://docs.ted.europa.eu/api/2.0/endpoints/enotices2-ted-europa-eu-esenders.html` - Publication API pre eSenderov; ak sa oznamenie podava cez API, cely jeho zivotny cyklus treba riadit cez API a nie cez UI eNotices2.
- `https://enotices2.ted.europa.eu/about` - eNotices2 pre kupujucich z EHP, format eForms.

## Neistoty

1. **Vestnik VO ako otvorene data** - vyhladavanie vratilo existujuce dataset stranky na `data.slovensko.sk` (napr. "Vestnik 225/2025", "Vestnik 217/2025", "Vestnik 76/2026"), ale portal je JavaScriptova aplikacia a WebFetch z nej nacital len titulok. **Nepodarilo sa mi overit format distribucie, download URL, licenciu ani frekvenciu.** To isté pri `data.slovensko.sk/datasety?poskytovatel=...`. Treba overit priamo v prehliadaci alebo cez SPARQL endpoint.
2. **Obsah EKS API prirucky** - overil som, ze prirucky existuju a ze sa pouziva OAuth. **Neotvoril som PDF**, takze neviem ktore operacie su citanie a ktore zapis, ci sa da zalozit zakazku programovo, ani ci je rozhranie dostupne kazdemu obstaravatelovi alebo len "spravcom a prevadzkovatelom IS" po dohode.
3. **RPVS Swagger** - `https://rpvs.gov.sk/opendatav2/swagger` vratil len prazdny Swagger UI shell (JS aplikacia). Existenciu a verziu potvrdzuje oficialna stranka MS SR, ale **konkretne endpointy, autentifikaciu a limity som nevidel.**
4. **Register upadcov OpenAPI** - URL `obcan.justice.sk/pilot/api/ress-isu-service/swagger-ui/index.html` obsahuje slovo "pilot"; **nenacital som ju**, takze neviem ci je produkcna a co presne pokryva.
5. **api.statistics.sk/rpo/v1/** - direktne nacitanie **timeoutovalo po 60 s** (1 pokus). Dokumentaciu mam z dvoch nezavislych oficialnych zdrojov, ale zivost produkcneho endpointu som nepotvrdil.
6. **UPVS / KEP** - integracne manualy UPVS nie su verejne, takze nemozem overit ci existuje sluzba na programove **overenie KEP** (validaciu podpisu) volatelna z aplikacie tretej strany. SNCA uvadza kvalifikovanu validacnu sluzbu zdarma pre OVM, ale bez technickej dokumentacie. Toto je kriticka neistota, lebo platforma stoji na podpisovani.
7. **e-Certis API** - zadnu oficialnu REST dokumentaciu som nenasiel. URL `https://esentool.ted.europa.eu/api/espd/v1.0/notice` pochadza zo **sekundarneho zdroja** (dokumentacia narodnej ESPD sluzby) a neoveril som ju.
8. **ERANET, Tendernet a dalsie certifikovane elektronicke prostriedky** - v tomto kole som ich nestihol preverit. Zoznam certifikovanych systemov by mal byt na UVO, ale stranka o certifikacii aukcnych systemov, ktoru som nacital, neobsahovala strojovo citatelny zoznam.
9. **ITMS2014+ Open Data API** - manual je `.docx` na partnerskadohoda.gov.sk; **neotvoril som ho.** Podla sekundarneho zdroja je ITMS uz prepojene s Vestnikom UVO a EKS, co by mohol byt vzor integracie.
10. **Josephine** - neexistuje verejna developer dokumentacia, ktoru by som vedel citovat. Nemozno vylucit, ze API existuje na poziadanie pre zakaznikov.

## Dopady na platformu

### A. Systemy BEZ API - tu bude platforma nutne potrebovat rucny vstup alebo scraping

Toto je najdolezitejsi zoznam v celom dokumente. Kazdy riadok je bod, kde sa "clovek len schvaluje a podpisuje" **laame**.

| System | Co sa tam nedostane strojovo | Nutne riesenie | Aka to je zavislost |
|---|---|---|---|
| **IS EPVO (isepvo.sk)** | Vyhlasenie zakazky, nahranie sutaznych podkladov, komunikacia s uchadzacmi, prijem a otvaranie ponuk, e-aukcia, zapisnice | Rucne prepisanie do portalu, alebo browser automation (scraping/RPA) | **Najtvrdsia zavislost cele platformy.** Pokryva P07-P09, P11, P13-P15. Prevadzkovatelom je Urad vlady SR, nie UVO, takze aj rokovanie o API ide inam, ako by clovek cakal. Browser automation na statnom portale je pravne aj prevadzkovo riskantna (ToS, kapcha, zmeny UI, zodpovednost za podanie). |
| **IS eForms UVO (eforms.uvo.gov.sk)** | Podanie oznamenia do Vestnika VO | Rucne. Pre TED existuje Publication API, pre slovensky Vestnik nie | Kriticka pre **P07 a P18**. Ironia: EU kanal (TED) je lepsie otvoreny ako narodny. |

Toto treba rozhodnut prvé. |

### B. Kde sa da postavit skutocna automatizacia hned

1. **Overovanie uchadzacov (P12, P17)** - najsilnejsie miesto. RPO + RPVS + RUZ + Financna sprava su vsetky dokumentovane API. Jedna dotazovacia vrstva nad nimi pokryje vacsinu § 32 kontrol a overenie RPVS pred podpisom zmluvy.
2. **Nadlimitne zverejnovanie do TED (P07, P18)** - TED Publication + Validation API umoznuju postavit vlastny **eSender**. Platforma moze generovat eForms, validovat a odoslat bez cloveka. Toto je jedina cast VO, kde je plna automatizacia zverejnenia realne dosiahnutelna dnes.
3. **Prieskum trhu a PHZ (P02)** - TED Search API + TED Open Data + Vestnik datasety + CRZ + UVOstat. Da sa postavit cenova databaza na urcovanie PHZ z historickych vysledkov.
4. **Archivacia a sprava o zakazke (P19)** - vsetky citacie kanale su k dispozicii, zbieranie dokazov je automatizovatelne.

### C. Architektonicke dosledky

- **Platforma nemoze byt "elektronicky prostriedok VO" v zmysle zakona bez integracie na IS EPVO alebo bez vlastnej certifikacie.** Realisticke pozicovanie je **pre-processing a post-processing vrstva**: pripravi vsetko (dokumenty, overenia, eForms), clovek to prenesie do IS EPVO alebo EKS, platforma potom vysledok naspat nacita a spracuje. Integracia na EKS je jediny slovensky VO system s dokumentovanym rozhranim, takze **EKS a zakazky s nizkou hodnotou su najrychlejsia cesta k funkcnemu produktu**.
- **Dva rezimy zapisu treba oddelit v architekture:** (1) plne automatizovany zapis - TED, EKS, (2) asistovany rucny zapis - IS EPVO, IS eForms UVO, CRZ. Rezim (2) potrebuje vlastny modul "pripraveny balik na prenesenie" s kontrolnym zoznamom a potvrdenim cloveka.
- **Kazdy scraper je pravna a prevadzkova zavislost, nie technicka drobnost.** Pri overovani podmienok ucasti je vystupom rozhodnutie s pravnymi ucinkami. Odporucanie: kazdy scrapovany udaj ukladat so snapshotom zdroja a casovou znackou, a nikdy nepouzit ako jediny dokaz bez potvrdenia cloveka.
- **Dve API vyzaduju kluc / dohodu:** TED (Publication, Validation) a Financna sprava (limit 1000 req/h). Financna sprava limit je nizky pri davkovom overovani vacsieho poctu uchadzacov - treba lokalnu kopiu datasetov, nie dotaz na kazdy ICO.
- **Frekvencia dat nie je realtime.** RPO sa aktualizuje v noci (zmeny za max. 24 h v API nie su), zdravotne poistovne raz mesacne k 20. dnu. Platforma musi pri kazdom overeni evidovat **k akemu datumu bol udaj platny**, lebo to je presne to, co kontrolny organ bude pytat.
- **Sledovat PPDS.** Ak SR prepoji svoje VO systemy na europsky Public Procurement Data Space, moze to byt prva realna sanca na strojovy pristup k narodnym datam VO. Zatiaľ bez technickych standardov.
